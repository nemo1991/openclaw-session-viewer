## 二、背景与目标

### 2.1 背景

v0.11.0 已封版，交付了会话体检（B1–B3）等核心洞察能力，但**导航层仍是「散落图标 + 局部工具条」形态**，用户在多个视图间移动成本高：

- **全局无统一导航**。`App.tsx`（`:60-98`）的 `<Routes>` **没有全局导航条**；顶部工具条（`search / refresh / graph / tools / settings` 图标）是 `SessionsRoute` 的**局部 `header.topbar`**（`routes/SessionsRoute.tsx:229-255`）。
- **Graph 页是导航孤岛**。`GraphExplorerRoute.tsx`（`:49-98`）内部只有 `explorer-tabs`（graph/analytics/health/rag），**无任何返回会话列表或其他视图的入口**，在 `/graph` 下只能靠浏览器后退。
- **体检入口深且文案过时**。首页进入 Graph 的按钮 `title="Graph Explorer (G1/G2/G3)"`（`SessionsRoute.tsx:240`）漏写 G4 体检；到达体检需「首页 → Network 图标 → /graph → 点 G4 tab」≥3 次点击，而体检是 v0.11 主交付能力。
- **详情/分析/Trajectory 页返回依赖 `navigate(-1)`**（`SettingsRoute.tsx:117` 等），无显式「回到会话列表」常驻入口。

### 2.2 要解决的问题

1. 任意页都能一键直达其他核心视图（会话 / 图探索 / 分析 / 体检 / 知识问答 / 工具 / 设置）。
2. 把 v0.11 体检能力从「二级 query tab」提升为「一级可达」，缩短洞察闭环。
3. 消除 Graph 页导航孤岛，不再依赖浏览器后退。
4. 统一导航心智模型，降低新用户学习成本。

### 2.3 成功指标与口径

| 指标                       | 定义                               | 目标值（估算） | 口径来源                         |
| -------------------------- | ---------------------------------- | -------------- | -------------------------------- |
| 到达体检的点击步数         | 首页 → 看到体检结果                | 3 → **1**      | 侧边栏「体检」项一步直达         |
| Graph 页返回首页的点击步数 | 在 /graph 回到会话列表             | 无入口 → **1** | 侧边栏「会话」项常驻             |
| 导航相关 E2E 回归通过率    | 改动后既有 graph/health E2E 仍通过 | 100%           | 保留 `?view=` 深链 + 重跑 `e2e/` |
| 一级导航项可达性           | 从任一一级路由能直达其余所有一级项 | 7/7            | 侧边栏常驻                       |

> 目标值为估算，落地后以 v0.11 A1 本地事件日志的导航点击数据为校正基准（见 §十）。

## 三、名词与术语定义

| 术语              | 定义                                                                              |
| ----------------- | --------------------------------------------------------------------------------- |
| 一级导航          | 直接映射到顶层路由/视图的导航项（会话、图探索、分析、体检、知识问答、工具、设置） |

## 四、需求范围

### 包含（In Scope）

- 新增全局布局 `AppLayout` + 常驻 `SideNav`（方案 α）。
- 7 个一级导航项，体检一步直达；Logo 可点回首页。

- 本 PRD 仅做导航连通（A1/A2）。首页筛选收敛（B1）、卡片分层（C1/C2）、操作密度收敛（D 组）属 v0.12 其余 PRD，不在本文件范围。

## 五、方案对比与选型说明

### 5.1 导航形态三方案（ROADMAP §5.1 扩展）

| 方案           | 描述                                                                | 优点                                                                             | 缺点                                                                   | 结论             |
| -------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------- |
| **α 侧边栏**   | 全局左边栏常驻 7 个一级项；顶部去掉散落图标；`?view=` 深链保留      | 桌面范式标准、体检升为一等公民、扩展性好（未来加视图不挤顶部）、彻底消除导航孤岛 | 占横向空间；需重构 `App.tsx` 全局布局与迁移 `SessionsRoute` topbar     | **拍板采用**     |
| β 顶部 tab     | 全局顶部一条 tab（会话/Graph/工具/设置）；Graph 内 G1–G4 仍为子 tab | 改动小、保留横向空间                                                             | 顶部与现有 title/操作冲突、拥挤；体检仍挤在 Graph 二级，未解决核心痛点 | 落选（作为兜底） |
| γ 仅补返回按钮 | 只在 Graph/详情页加返回，不动整体导航                               | 最小改动                                                                         | 不解决入口分散与体检深藏，治标                                         | 不采用           |

### 5.2 拍板理由（产品经理决策）

1. **产品形态匹配**：Tauri 桌面应用、本地宽屏，左侧栏是用户已习惯的桌面范式，横空间充足。
2. **核心痛点直击**：体检是 v0.11 主交付，必须一步可达；β/γ 仍把体检藏于 Graph 二级，等于未解决 §2.1 痛点。
3. **扩展性**：未来 v0.12+ 若加「脱敏导出」「成本异常」等视图，侧边栏加项即可，β 顶部会迅速拥挤。
4. **风险可控**：α 的牵连面（RK-4）通过「分两阶段小步合入」与「保留深链」对冲（见 §十一）。

### 5.3 落地形态（α 的具体定义）

- **侧边栏一级项**（每项 `navigate` 到对应路径，图标沿用 lucide）：

  | 项       | 路径                    | 图标（建议）    | 说明                           |
  | -------- | ----------------------- | --------------- | ------------------------------ |
  | 会话     | `/`                     | `MessageSquare` | 现有 SessionsRoute 首页        |
  | 图探索   | `/graph?view=graph`     | `Network`       | G1                             |
  | 分析     | `/graph?view=analytics` | `BarChart3`     | G2                             |
  | 体检     | `/graph?view=health`    | `Activity`      | G4（v0.11 核心，升为一等公民） |
  | 知识问答 | `/graph?view=rag`       | `Sparkles`      | G3                             |
  | 工具     | `/tools`                | `Wrench`        | 现有 ToolsRoute                |
  | 设置     | `/settings`             | `Settings`      | 现有 SettingsRoute             |

- **进入 `/graph` 后**：现有 `explorer-tabs`（G1/G2/G4/G3）**保留**，且与侧边栏以 URL 为单一真相源双向高亮（FR-N3）。
- **首页 topbar 迁移**：`SessionsRoute` 原有 `graph / tools / settings` 图标按钮（`:240-253`）移除（已由侧边栏承担）；`search`（打开 SearchPalette）与 `refresh`（同步）保留为**首页上下文操作**（或迁至侧边栏底部，见 FR-N7 Could）。
- **Logo**：侧边栏顶部应用名/Logo，`onClick → navigate('/')`（FR-N4）。

## 八、非功能需求

- **性能**：`SideNav` 为静态结构，不得因路由切换整体重挂载；高亮计算走轻量 `useLocation` 派生，避免额外渲染开销。
- **可访问性**：导航项用 `<nav aria-label>` + `<a>/<button>` 语义；当前项 `aria-current="page"`；支持键盘 Tab 聚焦与 Enter 激活。
- **视觉一致性**：沿用现有设计 token（`theme/tokens.css`、`global.css`）与 lucide 图标体系；侧边栏宽度、配色与现有 topbar 风格对齐。
- **响应式**：本期不做移动端（Won't）；桌面固定宽度侧边栏，不引入断点逻辑。

## 九、业务流程与状态流转

```
[应用启动]
   └─ AppLayout 渲染 SideNav（常驻）+ 右侧路由出口
        ├─ 默认 / → SessionsRoute（首页列表）
        ├─ 点侧边栏项 → navigate(对应路径) → 路由切换，SideNav 不卸载
        ├─ 进入 /graph?view=X → GraphExplorerRoute
        │     ├─ explorer-tabs 与 SideNav 以 URL 双向高亮
        │     └─ 点子 tab 或侧边栏子项均可切换 view
        └─ 点 Logo → navigate('/') 回到会话列表
```

状态要点：**SideNav 不随路由卸载**，仅右侧内容区切换；高亮态完全由 URL 推导，无独立选中 state，避免与子 tab 状态漂移。

## 十、数据与埋点需求

- **不引入任何网络上报**（D-2）。
- **可选本地事件（Could，非必须）**：复用 v0.11 A1 的本地 `event_log` 机制，可记录 `nav_item_click`（字段：`item`=侧边栏项名、`source`="sidenav"），**仅写本地 SQLite、零上传**，用于后续校正 §2.3「到达体检步数」等指标。
- 本期**不强制**新增埋点；若实现 FR-N7 折叠持久化，存于本地（`settings.json` 或 localStorage），无网络。

## 十二、异常处理清单

| 异常场景                                       | 处理                                                                              |
| ---------------------------------------------- | --------------------------------------------------------------------------------- |
| `?view=` 非法值（如 `?view=foo`）              | 沿用现有兜底：`GraphExplorerRoute` 纠正到 `graph`（`:29-33`）；侧边栏不高亮异常项 |

| 迁移后旧书签/分享链接（`/graph` 无 view）      | 默认落 `graph`（现有行为不变）                                                    |
