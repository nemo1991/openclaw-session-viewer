### 2.3 一个重要修正：埋点口径与战略冲突（PRD 变更请求）

v0.10 PRD 第十章写「埋点事件……**上报**字段：source / 会话数 / 是否真实口径」。在 D-2「本地优先、零上传、不引入账号体系」下，「上报」既无基础设施、也不该有。

**本版按需求变更流程处理（变更评估五要素）**：

| 要素         | 结论                                           |
| ------------ | ---------------------------------------------- |
| 影响范围     | 仅 PRD 第十章与 v0.11 的数据需求；不改功能行为 |
| 工期变化     | 无（改为本地事件日志，复用现有 SQLite）        |
| 成本变化     | 无新增服务/依赖                                |
| 风险变化     | 降低（消除与隐私定位的冲突）                   |
| 干系人一致性 | 需产品负责人确认（本规划默认按 D-2 执行）      |

**变更内容**：将「埋点上报」重定义为「**本地事件日志（local event log）**」——事件写入本地 SQLite，支撑成功指标口径与自查，**禁止任何网络请求**。PRD 第十章已相应修订；A1 已落地（`event_log` 表 + 3 事件 + 零上传门禁），实现见 PRD 15.6 与 QA 核验报告第八章。

- **本版目标**：让「洞察」从「用户自己翻 Analytics」升级为「系统主动标出异常会话」，同时把 v0.10 遗留的验收缺口补齐，使口径、指标、文档三者一致。
- **北极星（沿用）**：用户主动识别并复盘的高价值会话占比。

| 指标             | 定义                                          | 统计周期 | 目标值                                |
| ---------------- | --------------------------------------------- | -------- | ------------------------------------- |
| 体检标记有用率   | 被体检标记且用户确认「有用」的会话 ÷ 标记总数 | 周       | ≥ 70%（估算，需 A1 本地事件日志支撑） |
| 重试率算法准确率 | 评测集上判定正确率                            | 发布前   | ≥ 95%（沿用 v0.10 PRD，本版补评测集） |

| 契约一致率       | Rust/TS 归一化契约断言通过率                  | 每次构建 | 100%（已达成，本版保持）              |

> 所有目标值为估算/建议默认值，待真实数据校正；不使用未核实的外部数据。
