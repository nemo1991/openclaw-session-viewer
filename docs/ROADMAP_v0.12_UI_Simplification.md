## 二、现状诊断（基于代码的摩擦点，非臆测）

> 证据均来自当前 `main` 工作区源码。下一节需求与这些证据一一对应。

### 2.1 导航断裂：进了 Graph 找不到回首页的路

- `App.tsx` 的路由布局**没有全局导航条**；顶部工具条（`search / refresh / graph / tools / settings`）是 `SessionsRoute` 的**局部 `header.topbar`**（`routes/SessionsRoute.tsx:229-255`）。
- `GraphExplorerRoute.tsx` 内部只有 `explorer-tabs`（graph/analytics/health/rag），**无任何返回会话列表的入口**（`:49-98`）；从 `/graph` 返回首页只能依赖浏览器后退。
- `SettingsRoute` 用 `navigate(-1)` 返回（`:117`），`Graph` 页连这都没有。→ **用户在 Graph/体检页处于"导航孤岛"**。

### 2.2 体检入口深 + 文案过时

- 首页进入 Graph 的按钮 `title="Graph Explorer (G1/G2/G3)"`（`SessionsRoute.tsx:240`），**漏写 G4 体检**，用户无法从 tooltip 得知有体检功能。
- 到达体检需：首页 → Network 图标 → `/graph` → 点「G4 体检」tab = **≥3 次点击**，且体检是 v0.11 新交付的核心能力，不应藏在二级 query string 里。

### 2.3 首页筛选面板过载（14 个控件平铺）

- `SessionsRoute` 侧栏（`routes/SessionsRoute.tsx:262-382`）：3 个 checkbox（liveOnly / hasSubagents / last7Days）+ 4 个 source radio + agent×N + 2 个 checkbox（showHidden / showArchived）+ 搜索框，**无折叠、无"重置筛选"、无常用快捷入口**。
- 分组逻辑混合：OpenClaw 按 agent→workspace 二级，其余按 workspace（`SessionsRoute.tsx:132-177`），新用户理解成本高。

### 2.4 会话卡片信息过载，风险信号被淹没

- 单卡（`SessionsRoute.tsx:468-744`）承载：标题 + 5 类 badge（live / subagent / source / pin / hide）+ meta 行（时间·大小·消息数·模型·channel）+ firstPrompt 预览 + **最多 9 个 stat-chip**（thinking / tools / duration / error / repeat / idle / todo / tokens / compaction，`:586-714`）+ topTools + tags + **4 个常驻操作图标**（pin / hide / archive / rename，`:716-741`）。
- v0.11 体检标记（异常会话）无首页表面——用户得进 Graph 体检 tab 才知道哪条会话有问题，**风险信号没有前置到列表**。
- 重命名靠**双击标题**触发（`:521`，`renameHint`），可发现性差。

### 2.5 配置与查看分离

- 体检阈值在 `SettingsRoute`（`:277-337`，4 条规则），查看在 `GraphExplorerRoute` 的 HealthView——**"调阈值"与"看结果"跨两个一级页**，v0.11 已暴露此割裂但尚未收敛。

### 2.6 详情页动作密度高

- 代码注释自述 SessionHeader 曾抽离「12 button」（`SessionDetailRoute.tsx:35`），虽已分层（L0 chrome），但密度仍偏高，可进一步收敛。

## 三、目标与成功指标

- **本版目标**：让用户在 **1 次点击内** 到达任何核心视图（会话列表 / Graph / 体检 / 工具 / 设置）；首页首屏**只呈现高频信息**，低频操作收敛到折叠/悬浮/右键；把 v0.11 的"体检"能力前置到列表层。
- **北极星（沿用）**：用户主动识别并复盘的高价值会话占比。

| 指标                       | 定义                               | 目标值（估算）                        |
| -------------------------- | ---------------------------------- | ------------------------------------- |
| 到达体检的点击步数         | 首页 → 看到体检结果                | 3 → **1**（一级入口直达）             |
| Graph 页返回首页的点击步数 | 在 /graph 回到会话列表             | 无入口 → **1**                        |
| 首页首屏常驻筛选控件数     | 不滚动即见、默认展开的筛选控件     | 14 → **≤6**（高级项折叠）             |
| 卡片默认可见 chip 数       | 未展开时卡片上常驻的 stat-chip     | ≤9 → **≤3**（标题+meta+风险，余折叠） |
| 体检阈值调整跨页跳转次数   | 查看体检 → 改阈值 → 回看           | 跨页 1 → **0**（内联）                |
| 导航相关 E2E 回归          | 改动后既有 graph/health E2E 仍通过 | 100%（保留 ?view= 深链兼容）          |

> 目标值为基于当前代码控件数的估算，落地后以 A1 本地事件日志（v0.11 A1）的导航点击数据为校正基准；不使用未核实外部数据。

## 四、需求范围

### 包含（In Scope）

- A 组：统一一级导航 + 全局返回/首页入口（连通性，最高优先）。
- B 组：首页筛选面板收敛（折叠/重置/高频前置）。
- C 组：会话卡片信息分层 + 体检风险前置。
- D 组：操作密度与可发现性（悬浮/右键菜单、快捷键提示、配置内联）。

### 不包含（Won't，本期不做）

- 移动端 / 响应式重构、拖拽排序、自定义仪表盘、主题换肤扩展。
- ja-JP 等新增语言（D-3）；云同步 / 账号（D-2）。

### 5.1 A1 方案对比（需评审拍板）

| 方案                         | 描述                                                                                | 优点                                     | 缺点                                            | 推荐     |
| ---------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------- | ----------------------------------------------- | -------- |
